# Bioengineering Wearables Lab — Data Analysis Toolkit

Analysis code from my undergraduate research in a bioengineering healthcare
wearables lab. The work covered the wet-lab and computational sides of
developing wearable and point-of-care devices, with two main software
workstreams:

- **Electrochemistry data automation** — converting instrument exports into
  tidy datasets, integrating charge, extracting calibration slopes, and
  producing publication-style R figures.
- **Mental-stress signal processing** — ECG R-peak detection, RR-interval
  cleaning, heart-rate variability features, respiration peak/trough
  detection, and multi-panel report figures.

This repository consolidates the scripts that were actually used day-to-day.
It is deliberately closer to research code than to a packaged library:
configuration lives at the top of each script, and the workflows are designed
to be easy to inspect and adapt.

## What is included

| Area | What it does |
|---|---|
| `electrochemistry/ion_transport_charge` | Integrates chronoamperometry current traces to charge and finds the time window with the best calibration intercept / linearity. |
| `electrochemistry/open_circuit_potential` | Parses stepped OCP recordings, validates step sequences, computes mean OCP windows, and fits Nernst slopes. |
| `electrochemistry/randles_sevcik` | Extracts peak currents from cyclic voltammograms, fits peak current vs sqrt(scan rate), and estimates electrode area. |
| `mental-stress/ecg` | Detects R peaks, exports cleaned RR intervals, computes HRV/beat-level features, and plots a multi-panel report. |
| `mental-stress/respiration` | Detects inspiration/expiration peaks and troughs, exports interval series, computes breath features, and plots a report. |

## Methods at a glance

**Electrochemistry**

- Cumulative trapezoidal integration of current to charge.
- Linear regression of charge vs concentration across candidate time windows.
- OCP step validation and direction-aware Nernst slope fitting.
- Randles–Ševčík analysis: Estimating electroactive surface area through slope.

**ECG / HRV**

- Wavelet baseline removal and Butterworth band-pass filtering.
- R-peak detection with prominence and refractory-distance constraints.
- RR cleaning by physiological range, median deviation, and beat-to-beat
  difference thresholds.
- Time-domain metrics (HR, RMSSD, pNN50, SD1/SD2), frequency-domain metrics
  (VLF/LF/HF/LF-HF via Welch PSD), and the Baevsky stress index.

**Respiration**

- Band-pass filtering of the optical-encoder signal.
- Peak/trough detection for inspiration and expiration.
- Breath interval cleaning, rate, variability, and amplitude features.

## Quick start

Python 3.11+ is recommended (tested with Python 3.14). From the repository root:

```bash
python -m venv .venv
source .venv/bin/activate

# Core Python stack for every pipeline
pip install -r requirements.txt

# Optional: PalmSens .pssession conversion
pip install -r requirements-palmsens.txt
```

Generate the synthetic demo data and run the pipelines:

```bash
python examples/generate_synthetic_data.py

python examples/run_ecg_demo.py
python examples/run_respiration_demo.py
python examples/run_electrochem_demo.py
```

The demo writes generated CSVs and figures under `Data/` and the two
`mental-stress/*/output/` folders. All of those paths are gitignored.

Individual electrochemistry pipelines can also be run directly from the
repository root:

```bash
python electrochemistry/ion_transport_charge/main.py demo_ion
python electrochemistry/open_circuit_potential/main.py demo_ocp
```

The mental-stress exporters default to the full 1800 s protocol. Use the demo
runners for the 300 s synthetic recordings, or set `duration_sec` and the
window sizes in `CONFIG` before running them directly. See
`mental-stress/README.md`.

The R plotting scripts require `tidyverse`, `ggsci`, and `scales`. See
`electrochemistry/README.md` for details.

## Data availability and privacy

This repository contains **analysis code only**. No raw participant data,
subject identifiers, or laboratory recordings are included. The public
examples are deterministic synthetic signals generated by
`examples/generate_synthetic_data.py`.

Recordings are expected to use anonymised subject codes (`S01`, `S02`, ...).
The original analysis scripts were written around a private data layout; this
version uses the same structure under `Data/` with names removed.
